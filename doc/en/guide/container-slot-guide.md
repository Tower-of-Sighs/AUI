# ApricityUI `container` / `slot` / `recipe` Guide

Last updated: 2026-03-07

## 1. Overall Model

The current unified semantics are:

- Only one slot tag is used: `<slot>`
- Whether a slot is interactive is determined by the following mechanisms (highest priority first):
  - Slots generated by `recipe` are always non-interactive
  - CSS custom property `--aui-slot-interactive`
  - HTML attribute `interactive`
  - Whether the slot is bound to a data source (automatically interactive when inside a container and injected with a SlotView)
- Slots inside a container that are bound to a data source automatically gain interactivity and display real menu items
- Slots outside a container or without a binding serve as display-only, showing items set via innerText
- `container` uses `layout` to describe slot arrangement only
- Container titles are read only from the text of the first child element, such as `div` or `span`
- Slots generated by `recipe` are always non-interactive

## 2. `container` Attributes

### 2.1 `bind`

- Binds a data source such as `player`, `saved_data`, `block_entity`, or `entity`

### 2.2 `layout`

- Slot layout rules, either grid-style or presets
- Examples:
  - `layout="[27,3,9]"`
  - `layout="preset:player"`

Note: `layout` only affects arrangement. In normal cases it does not automatically create missing slot instances.

### 2.3 Title Rules

- The title is rendered inside the container
- The title source rule:
  - Only the text of the first child element is read
  - If the first child is missing or empty, the title area is not rendered and no placeholder is kept

Example:

```html
<container primary="true" bind="player" layout="preset:player">
  <div class="demo-title">My Title</div>
  <slot slot-index="0" repeat="36"></slot>
</container>
```

## 3. `slot` Attributes

### 3.1 `repeat`

- Batch generation using total-count semantics
- `repeat="36"` means a total of 36 slots, counting the template node itself as index 0

### 3.2 `slot-index`

- Local slot index
- Used inside a container to specify which data source position to bind to

### 3.3 `interactive`

- Explicitly controls whether the slot is interactive
- Values: `true` / `false` (or equivalents `1` / `0`, `yes` / `no`)
- Default behavior when not declared:
  - Slot bound to a data source → interactive
  - Unbound slot → non-interactive
  - Slot generated by recipe → always non-interactive
- Can also be controlled via CSS custom property `--aui-slot-interactive`

### 3.4 `disabled`

- Disables interaction (takes priority over `interactive`)

### 3.5 Display Item Attributes

- `innerText`: item literal (this is the only supported entry)
  - Item id: `minecraft:diamond`
  - Tag: `#minecraft:planks`
  - Id plus NBT: `minecraft:diamond_sword{Damage:12}`
  - Full ItemStack NBT: `{id:"minecraft:diamond",Count:1b,tag:{display:{Name:'{"text":"Preview"}'}}}`
  - Pipe-separated multiple candidates: `minecraft:iron_ingot|minecraft:gold_ingot|minecraft:copper_ingot`
  - JSON Ingredient array: `[{"item":"minecraft:oak_log"},{"item":"minecraft:birch_log"}]`
- `cycle-interval` (alias `rotate-interval`): candidate rotation interval in ms, default 1000ms, minimum 200ms
- `cycle`: whether to enable rotation (`true` / `false`), default `true`

### 3.6 Rendering Control

- `render`: controls what is rendered
  - `all` (default): render background + item
  - `item`: render item only
  - `bg`: render background only
  - `none`: render nothing
- `render-bg` / `render-item`: individual control for background/item rendering
- CSS custom properties: `--aui-slot-render-bg`, `--aui-slot-render-item`

### 3.7 Size and Style

- `size` (alias `slot-size`): slot pixel size
- `iconScale`: item icon scale factor
- `padding`: item padding
- CSS custom properties: `--aui-slot-size`, `--aui-slot-icon-scale`, `--aui-slot-padding`
- CSS such as `position/top/left/...` can still be used for manual layout

## 4. Player Container Default 36 Slots

When `container.bind="player"` and there are no slots inside the container, the system injects player inventory slots implicitly:

- `inv`: 27 slots (3x9)
- `hotbar`: 9 slots (1x9)
- Default gap: `4px`

If you already declare slots explicitly, this implicit injection does not happen.

## 5. `recipe` Rules

- `<recipe>` can be used independently in normal HTML display
- Multiple `<recipe>` tags may exist inside a container, each with its own sub-layout
- Slots generated by `recipe` are always non-interactive and never bind to a real menu
- Syntax: `<recipe type="...">recipe_id</recipe>`
- `type` is required and validated strictly. Recommended values:
  - `crafting_shaped`
  - `crafting_shapeless`
  - `smelting` / `blasting` / `smoking` / `campfire_cooking`
  - `stonecutting`
  - `smithing`

## 6. Examples And Entry Points

- `minecraft:diamond` -> `run/apricity/test/index.html`
- `minecraft:emerald` -> `run/apricity/test/saveddata_player.html`
- `minecraft:amethyst_shard` -> `run/apricity/test/virtual_container.html`
- `minecraft:nether_star` -> `run/apricity/test/recipe_showcase.html`

Example snippet:

```html
<container primary="true" bind="saved_data" layout="[9,3,3]">
  <div class="demo-title">SavedData Storage (9 slots, primary)</div>
  <slot repeat="9" slot-index="0"></slot>
</container>

<container bind="player" layout="preset:player">
  <div class="demo-title">Player Inventory (36 slots)</div>
  <slot repeat="36" slot-index="0"></slot>
</container>

<slot>{id:"minecraft:diamond",Count:12b,tag:{display:{Name:'{"text":"Example Item"}'}}}</slot>
<recipe type="crafting_shaped">minecraft:crafting_table</recipe>
```
