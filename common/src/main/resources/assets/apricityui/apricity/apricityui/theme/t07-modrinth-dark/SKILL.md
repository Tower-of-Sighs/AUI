# Modrinth Dark — Design Skill

本文件是 `t07-modrinth-dark` 的设计与代码生成规范。目标是在保留 Modrinth 暗色主题的青绿品牌氛围和柔和多层表面的同时，生成符合 ApricityUI 主题契约、在暗背景下可读且交互完整的界面。

## 何时使用

- 为 Modrinth 风格的项目浏览、内容目录、设置、仪表板和社区界面设计暗色页面。
- 为 ApricityUI 生成与 `t07-modrinth-dark` 配合的组件、页面标记和交互状态。
- 审核暗色界面中的表面层级、文字对比、选中状态和浮层可读性。

## 如何使用

- 将本文件作为暗色 UI 的强制视觉约束，再补充具体产品、页面结构和内容。
- 生成后逐项检查暗色表面、文字、语义色、禁用态和键盘焦点。
- ApricityUI 中优先复用现有主题类与 token；不要在业务标记中写死一套平行配色。

## 设计原则

- 延续 Modrinth 的产品语言：圆润、友好、内容优先，品牌绿鲜明但面积克制。
- 暗色不是简单反相。页面底层、内容表面、输入面、浮层应以不同亮度建立清楚层级。
- 正文采用柔和浅灰而非纯白，标题才使用高亮文字；辅助文字仍需满足可读性。
- 品牌填充、语义反馈和暗色表面文字是不同角色，分别选色，不混用一个 token。
- 可借鉴按钮、输入、卡片、胶囊开关和滑杆的比例；不复制 Modrinth logo、插画、品牌图案或业务 Vue 代码。

## 颜色与表面

| 角色 | Token / 色值 | 用途 |
| --- | --- | --- |
| 页面底层 | `--surface-1: #16181c` | 页面与大背景 |
| 次级底层 | `--surface-2: #1d1f23` | 输入槽、代码和凹陷区域 |
| 卡片表面 | `--surface-3: #27292e` | 卡片、菜单与主要面板 |
| 高亮表面 | `--surface-4: #34363c` | 控件、raised surfaces |
| 分隔线 | `--surface-5: #42444a` | 描边、分隔和轨道 |
| 主文字 | `--ink: #b0bac5` | 正文 |
| 标题文字 | `--heading: #ffffff` | 标题和重要标签 |
| 次级文字 | `--ink-muted: #96a2b0` | 帮助文本与非活动信息 |
| 品牌绿 | `--brand: #1bd96a` | 主操作和品牌状态 |
| 品牌填充文字 | `--accent-text: #000000` | 品牌填充表面上的文字 |
| 错误 | `--red: #ff9fae` | 暗底错误文字、语义标签 |
| 信息 | `--blue: #90c4ff` | 链接和信息状态 |
| 辅助强调 | `--purple: #dab2ff`，`--warning-text: #ffc171` | 紫色状态与警告 |

主色块上使用黑色或深色前景；正文保持灰白。柔和状态底色分别使用 `--success-soft`、`--warning-soft`、`--danger-soft`、`--info-soft`、`--purple-soft`。特别注意错误、警告等小字号文字对比度，不要直接将饱和色阶中较暗的品牌值作为暗底文字。

## 排版与布局

- 正文字体使用 Inter 风格系统无衬线栈；代码、标识符和快捷键使用等宽字体。
- 正文约 16px，辅助文字约 14px；标题较粗、紧凑，明确高于正文层级。
- 使用 4/8/16/24/32px 的间距阶梯。卡片内容以留白分区，不套叠多层容器。
- 卡片采用一像素表面描边、约 16px 圆角和低强度阴影；下拉和弹层可以使用稍强的浮层阴影。
- 桌面控制内容最大宽度；移动端单列布局，表格在局部容器内横向滚动。

## 组件规则

### 按钮

- 主操作使用亮品牌绿填充、近黑文字；次级按钮使用深灰 raised surface 和柔和内描边；tertiary 操作保持透明。
- 中号按钮约 36px 高、12px 圆角，文字 16px / 600；小按钮约 28px 高。
- 危险按钮采用粉红错误色，并使用足够对比的近黑前景；不要让危险态看起来像主操作。
- hover 只轻微调整亮度或表面；active 允许很小的按下反馈，不能引发布局偏移。
- 加载符号必须在按钮自己的填充色上清楚可见，禁用加载时仍需辨认其状态。

### 卡片与面板

- 卡片用 `surface-3`，边缘用 `surface-4`；大容器层级低于菜单、弹窗等浮层。
- 标题使用高亮文字和较重字重，正文使用柔和主文字；footer 以细分隔线区分。
- 彩色边框仅作为明确的语义强调，不能给普通卡片普遍添加霓虹描边。

### 表单、复选框与开关

- 输入框约 36px 高、12px 圆角，使用深 raised surface、细描边和清晰 placeholder。
- 聚焦以品牌色边框和焦点环反馈；错误需配合错误文字或图标，而非仅靠红色。
- 复选框约 20px，6px 圆角；开关约 48×24px，滑块圆点约 16px。开关打开时使用品牌绿底和黑色圆钮。
- 原生 checkbox/radio 必须保留键盘与禁用行为，使用主题 accent 色。
- 禁用开关保留开/关位置；禁用元素悬停时不应再次变亮、变色或缩放。

### 滑杆与进度

- 轨道约 6px 高，圆角胶囊；品牌色显示已填充区域，滑块约 10×32px。
- 在暗背景上，轨道与圆钮应有可辨差异；禁用态同时弱化轨道、填充和滑块但仍能识别位置。
- 数值必须有独立文本标签；设置行中的滑杆获得剩余宽度且窄屏不挤出容器。

### 导航、列表与数据

- 导航、列表默认用透明或轻表面；活动项使用低饱和品牌 tint 底色，前景保持高对比。
- 表格用真实 table 与自动列宽；横向分隔、表头 raised surface、轻微行 hover。
- 避免在所有列表项上使用饱和品牌填充；hover 与 active 必须有不同表现。

### 下拉、菜单与提示

- 下拉和菜单使用 `surface-3/4`、细描边、约 12px 圆角与受控浮层阴影。
- 展开箭头必须同步旋转；选中项有勾选或其它形状标记；长菜单限高可滚动。
- Tooltip 在 hover、focus 和显式展开时出现；四向定位准确，短触发器不压缩内容宽度。

### 模态、抽屉与反馈

- 遮罩是独立元素；模态、抽屉使用较高表面层级和可控投影，主体区可独立滚动。
- 通知和状态提示用暗色 tint 背景加清晰文字；选择既有粉彩语义前景，不将深色模式的鲜亮度误用成低对比暗色文字。
- 移动端 modal/drawer 减小外围 padding，保证可操作区域不溢出视口。

## 状态与可访问性

- 交互组件覆盖默认、hover、active、键盘焦点、disabled；适用组件还需覆盖选中、展开、错误、成功和加载。
- 焦点环必须可见并使用 outline；不要依赖 box-shadow 才能看见键盘焦点。
- 禁用态覆盖 `.disabled`、`[disabled]` 和 `[aria-disabled="true"]`，且 hover 前后视觉稳定。
- 勾线、箭头保持空心透明背景；开关钮、radio 圆点等填充图元可以单独调整。
- 状态不能只靠颜色表达；遵守 `prefers-reduced-motion`，非浏览器引擎可用 `data-motion="reduced"` 关闭动效。

## 禁止项

- 禁止将亮色主题直接反相；逐个判断文字、表面、语义色和强调色角色。
- 禁止纯黑大面积死底搭配低对比深灰文字；也不要让所有表面颜色趋同。
- 禁止在暗底上使用对比不足的深色彩色文字，尤其是小号 badge、alert 和 link。
- 禁止把品牌绿、紫色发光或渐变作为装饰性全局效果；不要使用玻璃拟态。
- 禁止为了复刻上游页面而引入品牌 logo、插画、无关图片或额外运行时依赖。
- 禁止破坏 AUI 核心类、状态钩子或最小标记契约。

## ApricityUI 主题接口

使用 `t07-modrinth-dark` 根作用域及现有组件类/token。暗色主题不铺写作用域根的 `background`，页面由 `--canvas` token 提供底色。保持通用语义：`--ink` 是正文、`--heading` 是高亮文字、`--brand` 是绿填充、`--accent-text` 是强调底上文字。

状态写法需兼容 `.on` / `:checked` / `[checked]` / `[aria-checked="true"]` / `[data-state="on"]`，活动状态 `.active` / `[aria-selected="true"]` / `[data-state="active"]`，展开 `.open` / `.show` / `[data-state="open"]` / `[aria-expanded="true"]` / `:focus-within`，禁用 `.disabled` / `[disabled]` / `[aria-disabled="true"]`。

## 生成后自检

1. 页面底层、卡片、raised surface、输入区、菜单浮层有明确层级且暗色统一。
2. 主要操作品牌绿填充可读；错误、警告、信息文字在对应 tint 底色上达到可读对比度。
3. 320px/390px 无页面横向溢出，表格只在自身容器内滚动。
4. 开关禁用不丢失选中位置；所有 disabled hover 前后样式稳定。
5. 键盘可访问所有交互组件，焦点环足够清晰；减少动态效果不丢失状态反馈。
6. 组件遵循 AUI 核心接口，不引入额外 DOM 要求、品牌资产或运行时依赖。
